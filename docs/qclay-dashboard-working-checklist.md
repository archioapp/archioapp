# ARCHIO Dashboard — QClay Working Checklist

**Use this document for meetings, Figma planning, and progress tracking.**  
The full functionality and rationale live in `qclay-dashboard-page-inventory-master.md`.

## Status key

- **A — Retain:** substantial product already exists; refine it.
- **B — Redesign:** existing page is useful but requires new architecture/hierarchy.
- **C — Prototype:** useful modules exist but not a coherent final page.
- **D — New:** design from zero.

## Non-negotiable product structure

1. Flight Deck
2. Community
3. Decision Desk
4. Trading DNA
5. The Marketplace
6. Portfolio
7. Net Worth
8. AI Verified Track Record
9. Social Network

**Flight Deck is the persistent workspace.** Other systems open as a peek panel, focused overlay, or deep-work page. **Archio AI is available everywhere.** The verified record is the data spine beneath every locked decision.

# 4. MVP clickable journey QClay should prototype

1. [ ] User opens **Morning Brief**.
2. [ ] Opens affected instrument in **Flight Deck** without losing context.
3. [ ] Asks **Archio AI** to mark a level on the chart.
4. [ ] Opens a **Community Live Room** in a slide-in/overlay.
5. [ ] Uses **Catch Me Up** and selects a source thesis.
6. [ ] Converts thesis into **Create Forecast** with attribution.
7. [ ] Locks the forecast.
8. [ ] Uses **Decision Builder** and signs a **Pre-Trade Contract**.
9. [ ] Simulates or records execution.
10. [ ] Receives an **Auto-Journal** entry.
11. [ ] Completes **Trade Review**.
12. [ ] Sees the locked event in **Private Record Center**.
13. [ ] Opens the privacy-safe result on **Public Trader Passport**.

This journey is the minimum proof that the dashboard is a connected system rather than a collection of pages.
